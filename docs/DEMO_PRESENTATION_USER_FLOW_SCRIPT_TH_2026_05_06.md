# Demo Presentation Script - User Flow ของแอพ Calories Guard

เอกสารนี้เป็นสคริปต์สำหรับพูดนำเสนอและเดโมการใช้งานแอพ Calories Guard ต่อกรรมการ โดยเน้นตอบคำถามหลักว่า:

- ผู้ใช้ทำอะไรได้บ้าง
- Flow การทำงานของผู้ใช้เป็นอย่างไร
- ระบบคำนวณและช่วยตัดสินใจตรงไหน
- ระบบป้องกันความเสี่ยงและแจ้งเตือนผู้ใช้อย่างไร
- จุดเด่นของแอพต่างจากแค่แอพบันทึกแคลอรี่ทั่วไปอย่างไร

## 1. โครงเวลานำเสนอ

### เวอร์ชัน 10-12 นาที

| ช่วง | เวลา | เนื้อหา |
|---|---:|---|
| เปิดเรื่อง | 1 นาที | ปัญหาและเป้าหมายของแอพ |
| สมัครและ onboarding | 2 นาที | consent, profile, BMI, goal, allergy |
| หน้าหลัก | 2 นาที | dashboard, calories, macro, BMI, notifications |
| บันทึกอาหารและน้ำ | 3 นาที | meal log, AI estimate, allergy warning, water safety |
| แนะนำอาหารและสูตร | 2 นาที | food recommendation, recipe, add to log |
| Progress, AI Coach, gamification | 2 นาที | progress, chat, exercise, reward |
| ปิดท้าย | 1 นาที | สรุป value และ safety |

### เวอร์ชัน 18-20 นาที

ใช้ flow เดียวกัน แต่เพิ่มการอธิบาย backend/DB/guardrail หลังแต่ละหน้าจอ และเปิด progress หรือ profile เพิ่ม

## 2. Opening Script

> สวัสดีครับ วันนี้ผมจะเดโมแอพ Calories Guard ซึ่งเป็นแอพช่วยติดตามโภชนาการและพฤติกรรมสุขภาพ โดยเป้าหมายหลักไม่ใช่แค่ให้ผู้ใช้จดแคลอรี่ แต่ช่วยให้ผู้ใช้เข้าใจว่าแต่ละวันควรกินเท่าไหร่ กินอะไรไปแล้ว ขาดอะไร เกินอะไร และควรปรับพฤติกรรมอย่างไรให้ปลอดภัยตามเป้าหมายของตัวเอง

> แอพนี้ออกแบบสำหรับผู้ใช้ที่มีเป้าหมายต่างกัน เช่น ลดน้ำหนัก เพิ่มกล้ามเนื้อ หรือรักษาน้ำหนัก ระบบจะเริ่มจากข้อมูลพื้นฐานของผู้ใช้ แล้วคำนวณ BMI, BMR, TDEE, เป้าหมายแคลอรี่ และสารอาหารหลัก จากนั้นเชื่อมกับการบันทึกอาหาร น้ำ น้ำหนัก การแจ้งเตือน AI Coach และระบบ gamification เพื่อช่วยให้ผู้ใช้ทำต่อเนื่องได้จริง

> ในเดโมนี้ผมจะพาเดิน flow แบบผู้ใช้จริง ตั้งแต่สมัครครั้งแรก ไปจนถึงการใช้งานประจำวัน

## 3. One-Liner สำหรับอธิบายแอพ

ถ้ากรรมการถามว่า “แอพนี้คืออะไร” ให้ตอบสั้นๆ:

> Calories Guard คือแอพติดตามโภชนาการที่คำนวณเป้าหมายรายบุคคลจากข้อมูลผู้ใช้ แล้วช่วยบันทึกอาหาร น้ำ น้ำหนัก วิเคราะห์ความคืบหน้า แนะนำอาหาร เตือนความเสี่ยง และใช้ AI Coach ช่วยตอบคำถามด้านอาหารอย่างปลอดภัย

ถ้าต้องพูดแบบสั้นมาก:

> แอพนี้ช่วยให้ผู้ใช้รู้ว่า วันนี้กินพอไหม กินเกินไหม ขาดสารอาหารอะไร และควรเลือกอาหารอย่างไรให้ตรงกับเป้าหมายสุขภาพของตัวเอง

## 4. Demo Setup ก่อนขึ้นนำเสนอ

เตรียมไว้ก่อนเริ่ม:

- เปิด emulator หรือมือถือจริงไว้หน้า login
- เตรียมบัญชี demo ที่ login ได้แล้ว
- เตรียมข้อมูลผู้ใช้ demo:
  - เพศ: หญิงหรือชาย
  - อายุ: 25-35 ปี
  - น้ำหนักและส่วนสูงที่ทำให้ BMI เห็นผลชัด เช่น BMI มากกว่า 23
  - เป้าหมาย: ลดน้ำหนัก
  - allergy: เลือกอย่างน้อย 1 อย่าง เช่น อาหารทะเล
- เตรียมอาหารตัวอย่าง:
  - ข้าวกะเพราไก่
  - ไข่ต้ม
  - ต้มยำกุ้ง หรือเมนูที่ชน allergy เพื่อโชว์ warning
- เตรียมคำถาม AI:
  - “วันนี้กินอะไรดีถ้าอยากลดน้ำหนัก”
  - “โปรตีนวันนี้พอไหม”
  - “มื้อเย็นควรกินอะไรถ้าเหลือแคลอรี่น้อย”
- เตรียมเดโมน้ำ:
  - หลัง 18:00 หรือปรับวันย้อนหลัง เพื่อโชว์ warning ดื่มน้ำน้อย

## 5. Flow รวมของผู้ใช้

```text
สมัคร/เข้าสู่ระบบ
  -> ยินยอมข้อมูลส่วนบุคคล
  -> กรอกเพศ วันเกิด น้ำหนัก ส่วนสูง
  -> เลือกระดับกิจกรรม
  -> ระบบคำนวณ BMI และประเมินความเสี่ยง
  -> เลือกเป้าหมาย: ลดน้ำหนัก / เพิ่มกล้าม / รักษาน้ำหนัก
  -> ตั้งน้ำหนักเป้าหมายและระยะเวลา
  -> เลือกอาหารที่แพ้
  -> เข้าหน้าหลัก
  -> บันทึกอาหาร น้ำ กิจกรรม น้ำหนัก
  -> ดู dashboard, macro, progress, recommendation, AI Coach
  -> รับแจ้งเตือนและปรับพฤติกรรม
```

## 6. Demo Part 1 - สมัครและเข้าสู่ระบบ

### สิ่งที่ทำบนจอ

1. เปิดหน้า Welcome
2. ไปหน้า Register หรือ Login
3. อธิบาย email verification แบบเร็ว
4. Login เข้าแอพ

### Script ที่ใช้พูด

> ส่วนแรกคือระบบบัญชีผู้ใช้ ผู้ใช้สามารถสมัครด้วยอีเมลและรหัสผ่าน ระบบมีการยืนยันอีเมลก่อนใช้งาน เพื่อป้องกันบัญชีปลอมและทำให้ข้อมูลสุขภาพผูกกับเจ้าของบัญชีจริง

> หลังจาก login แล้ว แอพจะเข้าสู่ onboarding เพื่อเก็บข้อมูลที่จำเป็นต่อการคำนวณ ไม่ได้เก็บทุกอย่างโดยไม่มีเหตุผล แต่เก็บเฉพาะข้อมูลที่ใช้คำนวณและปรับคำแนะนำ เช่น เพศ อายุ น้ำหนัก ส่วนสูง เป้าหมาย และการแพ้อาหาร

### สิ่งที่กรรมการควรรู้

- มี authentication
- มี email verification
- มี consent ก่อนเก็บข้อมูลสุขภาพ
- ข้อมูลสุขภาพใช้เพื่อคำนวณ personalized target

## 7. Demo Part 2 - Consent และข้อมูลพื้นฐาน

### สิ่งที่ทำบนจอ

1. เปิดหน้า Data Consent
2. กดตกลง
3. กรอกเพศ วันเกิด น้ำหนัก ส่วนสูง

### Script

> ก่อนเริ่มใช้งาน แอพแสดงหน้า consent เพื่ออธิบายว่าข้อมูลส่วนบุคคลและข้อมูลสุขภาพจะถูกใช้เพื่ออะไร เช่น ใช้คำนวณ BMI, BMR, TDEE และเป้าหมายโภชนาการ

> จากนั้นผู้ใช้กรอกข้อมูลพื้นฐาน ได้แก่ เพศ อายุ น้ำหนัก และส่วนสูง ข้อมูลชุดนี้เป็น input หลักของสูตรสุขภาพ เช่น BMI และ BMR

> จุดสำคัญคือแอพไม่ได้ให้ผู้ใช้เลือกเป้าหมายแบบลอยๆ แต่ให้ระบบคำนวณจากข้อมูลจริงก่อน เพื่อให้คำแนะนำเหมาะกับตัวผู้ใช้มากขึ้น

### Technical Note ถ้าถูกถาม

> ข้อมูลนี้ถูกส่งไป backend และเก็บในตาราง users จากนั้น backend จะใช้เป็นฐานสำหรับคำนวณ target calories และ target macros

## 8. Demo Part 3 - BMI และ Activity Level

### สิ่งที่ทำบนจอ

1. เปิดหน้า activity level
2. ชี้ให้ดู BMI card
3. ชี้ให้ดูเกณฑ์ BMI สำหรับชาวเอเชีย
4. เลือก activity level

### Script

> หลังกรอกข้อมูลพื้นฐาน ระบบจะแสดงค่า BMI และจัดกลุ่มความเสี่ยงตามเกณฑ์สำหรับชาวเอเชีย เพราะ cutoff ของคนเอเชียจะเริ่มเตือนความเสี่ยงตั้งแต่ BMI 23 และความเสี่ยงสูงขึ้นชัดเจนตั้งแต่ 27.5

> ต่อมาผู้ใช้เลือกระดับกิจกรรม เช่น นั่งทำงานเป็นหลัก ออกกำลังกายเล็กน้อย หรือออกกำลังกายมาก ข้อมูลนี้ใช้คำนวณ TDEE ซึ่งเป็นพลังงานที่ร่างกายใช้ต่อวัน

> พูดง่ายๆ คือ BMR บอกว่าร่างกายใช้พลังงานพื้นฐานเท่าไหร่ ส่วน TDEE คือ BMR ที่ปรับด้วยกิจกรรมในชีวิตประจำวัน

### Formula Script

> สูตรหลักคือ TDEE = BMR คูณ activity factor จากนั้นระบบจะเอา TDEE ไปกำหนดเป้าหมายแคลอรี่ตามโปรแกรมของผู้ใช้

## 9. Demo Part 4 - เลือกเป้าหมายสุขภาพ

### สิ่งที่ทำบนจอ

1. เปิดหน้า Goal Selection
2. ชี้ให้ดู 3 โปรแกรม
3. เปิด dialog อธิบาย goal ถ้ามี
4. เลือก “ลดน้ำหนัก” หรือ goal ที่เตรียมไว้

### Script

> แอพแบ่งโปรแกรมหลักเป็น 3 แบบ คือ ลดน้ำหนัก รักษาน้ำหนัก และเพิ่มกล้ามเนื้อ แต่ละโปรแกรมใช้ logic ต่างกัน

> ถ้าผู้ใช้เลือก “ลดน้ำหนัก” ระบบจะตั้งเป้าให้กินต่ำกว่า TDEE แบบมี safety guardrail ไม่ให้ deficit รุนแรงเกินไป

> ถ้าเลือก “รักษาน้ำหนัก” ระบบจะตั้งเป้าใกล้เคียง TDEE เพื่อช่วยให้พลังงานสมดุล

> ถ้าเลือก “เพิ่มกล้ามเนื้อ” ระบบจะตั้งเป้าให้พลังงานสูงกว่า TDEE และให้โปรตีนสูงขึ้น เพราะการเพิ่มกล้ามต้องใช้ทั้งพลังงาน โปรตีน และการออกกำลังกายแบบแรงต้าน

### พูดให้ลื่นแบบสั้น

> จุดนี้คือหัวใจของ personalization ครับ แอพไม่ได้ใช้สูตรเดียวกับทุกคน แต่แยกตามเป้าหมายของผู้ใช้

### ถ้ากรรมการถาม “งานวิจัยเอามาใช้อย่างไร”

> เราใช้หลัก TDEE เป็นฐานกลาง แล้วปรับพลังงานตามเป้าหมาย เช่น deficit สำหรับลดน้ำหนัก, maintenance สำหรับรักษาน้ำหนัก และ surplus สำหรับเพิ่มกล้าม ส่วนโปรตีนใช้แนวคิดจาก sports nutrition โดยให้โปรตีนสูงขึ้นในกลุ่มลดน้ำหนักและเพิ่มกล้าม เพื่อช่วยรักษาหรือเพิ่มมวลกล้ามเนื้อ

## 10. Demo Part 5 - ตั้งน้ำหนักเป้าหมายและระยะเวลา

### สิ่งที่ทำบนจอ

1. เลือก target weight
2. เลือกระยะเวลา
3. ชี้ให้ดูคำแนะนำเรื่องความเร็วที่เหมาะสม

### Script

> หลังเลือกโปรแกรม ผู้ใช้ตั้งน้ำหนักเป้าหมายและระยะเวลา ระบบจะประเมินว่าการเปลี่ยนแปลงน้ำหนักต่อสัปดาห์เหมาะสมหรือเสี่ยงเกินไป

> เช่น ถ้าลดน้ำหนักเร็วเกิน ระบบจะเตือน เพราะ deficit ที่มากเกินไปอาจทำให้เหนื่อย หิวมาก เสียมวลกล้ามเนื้อ หรือทำต่อเนื่องไม่ได้

> เป้าหมายของเราไม่ใช่ให้ผู้ใช้ลดเร็วที่สุด แต่ให้ลดอย่างปลอดภัยและทำต่อได้

### Formula Script

> ระบบใช้แนวคิดโดยประมาณว่า 1 กิโลกรัมของน้ำหนักตัวสัมพันธ์กับพลังงานประมาณ 7,700 kcal แล้วเฉลี่ยเป็นรายวันผ่านระยะเวลาที่ผู้ใช้ตั้งไว้ จากนั้นนำไปปรับกับ TDEE

## 11. Demo Part 6 - การแพ้อาหาร

### สิ่งที่ทำบนจอ

1. เปิดหน้าเลือก allergy
2. เลือกอาหารทะเลหรือ allergen ตัวอย่าง
3. เข้าแอพแล้วลองเลือกอาหารที่ชน allergy

### Script

> อีกส่วนที่สำคัญคือการแพ้อาหาร ผู้ใช้สามารถเลือกสิ่งที่แพ้ เช่น อาหารทะเล นม ถั่ว หรือกลุ่มอื่นๆ

> ข้อมูลนี้ถูกนำไปใช้ทั้งในหน้าบันทึกอาหารและหน้าแนะนำอาหาร ถ้าอาหารมีส่วนผสมหรือวัตถุดิบที่ผู้ใช้แพ้ แอพจะแจ้งเตือนก่อน เพื่อให้ผู้ใช้ตัดสินใจเอง ไม่ใช่บันทึกเข้าไปแบบไม่รู้ตัว

### จุดขาย

> ตรงนี้ทำให้ recommendation ไม่ใช่แค่ “แคลอรี่เหมาะ” แต่ต้อง “ปลอดภัยสำหรับผู้ใช้คนนั้น” ด้วย

## 12. Demo Part 7 - หน้าหลัก Dashboard

### สิ่งที่ทำบนจอ

1. เข้า Home
2. ชี้ calorie ring/progress
3. ชี้ target calories
4. ชี้ macro cards
5. ชี้ BMI card
6. ชี้ notification icon
7. ชี้ Tamagotchi/gamification banner

### Script

> เมื่อเข้าสู่หน้าหลัก ผู้ใช้จะเห็นภาพรวมของวันนี้ทันที เช่น วันนี้กินไปกี่แคลอรี่ เป้าหมายคือเท่าไหร่ เหลืออีกเท่าไหร่ และสารอาหารหลักอย่างโปรตีน คาร์บ ไขมันอยู่ระดับไหน

> หน้านี้ออกแบบให้ตอบคำถามประจำวันของผู้ใช้ว่า “วันนี้ฉันอยู่ตรงไหนแล้ว” โดยไม่ต้องเข้าไปดูหลายหน้า

> ถ้าผู้ใช้กินใกล้เป้า เกินเป้า หรือมีความเสี่ยง เช่น deficit สูงเกินไป ระบบจะมี notification เพื่อเตือนให้ปรับพฤติกรรม

## 24. Safety และ Guardrails ที่ควรพูดให้กรรมการเห็น

### Script รวม

> สิ่งที่ผมให้ความสำคัญมากคือ safety guardrail เพราะแอพสุขภาพไม่ควรแค่บอกให้ผู้ใช้กินน้อยหรือกินเยอะ แต่ต้องป้องกันความเสี่ยงด้วย

> ตอนนี้ระบบมี guardrail หลัก เช่น:

- เตือนเมื่อกินแคลอรี่ต่ำเกินไป
- เตือนเมื่อ deficit เทียบ TDEE สูงเกินไป
- เตือนเมื่อกินต่ำต่อเนื่องหลายวัน
- เตือนเมื่อกินเกินเป้าหมายหรือใกล้ถึงเป้า
- เตือนเมื่อน้ำดื่มต่ำกว่าเป้าในช่วงเย็น
- เตือนเรื่อง allergy ก่อนเพิ่มอาหาร
- เตือนให้บันทึกน้ำหนักเมื่อไม่ได้อัปเดตนาน
- AI มี scope guard และไม่ควรวินิจฉัยโรค

> ดังนั้นระบบไม่ได้ออกแบบให้ผู้ใช้ไล่ตามตัวเลขอย่างเดียว แต่คอยบอกด้วยว่าพฤติกรรมแบบไหนอาจเสี่ยง

## 25. User Journey แบบเล่าเป็นเรื่องเดียว

ใช้ตอนกรรมการถามว่า “ขอเล่า flow ผู้ใช้แบบรวบรัด”

> ตัวอย่างผู้ใช้ชื่อสมหญิง ต้องการลดน้ำหนักอย่างปลอดภัย เริ่มจากสมัครและยืนยันอีเมล จากนั้นแอพให้ยินยอมการใช้ข้อมูลสุขภาพ แล้วกรอกเพศ อายุ น้ำหนัก และส่วนสูง ระบบคำนวณ BMI และพบว่าเริ่มมีความเสี่ยงตามเกณฑ์เอเชีย จึงแนะนำให้ตั้งเป้าลดน้ำหนักแบบค่อยเป็นค่อยไป

> สมญิงเลือกเป้าหมายลดน้ำหนัก ตั้งน้ำหนักเป้าหมายและระยะเวลา ระบบคำนวณ TDEE แล้วตั้ง target calories และ macro ให้เหมาะกับการลดน้ำหนัก โดยเน้นโปรตีนเพื่อช่วยรักษามวลกล้ามเนื้อ

> ในการใช้งานประจำวัน สมญิงเปิดหน้าหลักเพื่อดูว่าวันนี้กินไปกี่แคลอรี่และเหลืออีกเท่าไหร่ จากนั้นไปหน้าบันทึกอาหาร เลือกเมนูหรือพิมพ์อาหารผ่าน AI ระบบรวมสารอาหารและอัปเดต dashboard ทันที ถ้าเลือกอาหารที่แพ้ แอพจะเตือนก่อน ถ้ากินต่ำเกินไปหรือ deficit สูงเกินไป ระบบก็เตือนเพื่อความปลอดภัย

> เมื่อสมหญิงไม่รู้จะกินอะไรต่อ สามารถไปหน้าอาหารแนะนำ ดูสูตรอาหาร หรือถาม AI Coach ได้ และเมื่อใช้งานต่อเนื่อง แอพจะแสดง progress น้ำหนัก กราฟ สรุปผล และใช้ gamification ช่วยให้กลับมาบันทึกต่อทุกวัน

## 26. คำถามที่กรรมการอาจถาม และคำตอบที่ควรใช้

### Q1: ผู้ใช้ทำอะไรได้บ้างในแอพนี้?

> ผู้ใช้สามารถสมัครและยืนยันบัญชี ตั้งค่าโปรไฟล์สุขภาพ เลือกเป้าหมาย บันทึกอาหาร บันทึกน้ำ บันทึกน้ำหนัก ดู dashboard ดู macro ดู BMI ดู progress รับคำแนะนำอาหาร ดูสูตรอาหาร ถาม AI Coach รับการแจ้งเตือนด้านความปลอดภัย และใช้ระบบ gamification เพื่อสร้างแรงจูงใจ

### Q2: แอพต่างจากแอพบันทึกแคลอรี่ทั่วไปอย่างไร?

> แอพนี้ไม่ได้หยุดที่การจดแคลอรี่ แต่เชื่อมข้อมูลผู้ใช้เข้ากับการคำนวณเป้าหมายรายบุคคล มี allergy-aware recommendation, recipe nutrition, AI Coach, safety guardrails และ gamification เพื่อช่วยทั้งการตัดสินใจและการทำต่อเนื่อง

### Q3: ระบบคำนวณเป้าหมายอย่างไร?

> ระบบคำนวณ BMR จากข้อมูลเพศ อายุ น้ำหนัก ส่วนสูง จากนั้นคำนวณ TDEE ด้วย activity factor แล้วปรับเป้าหมายตาม goal type เช่น ลดน้ำหนักจะเป็น deficit, รักษาน้ำหนักจะใกล้ TDEE, เพิ่มกล้ามจะเป็น surplus พร้อมคำนวณ macro target ตามเป้าหมาย

### Q4: ถ้าผู้ใช้ตั้งเป้าหมายลดเร็วเกินไปจะเกิดอะไร?

> ระบบมี safety floor และ deficit warning เพื่อป้องกันเป้าหมายที่ต่ำเกินไป รวมถึงเตือนเมื่อผู้ใช้กินต่ำกว่าเกณฑ์หรือ deficit สูงเกินไป โดยเน้นให้ลดแบบปลอดภัยมากกว่าลดเร็วที่สุด

### Q5: AI เชื่อถือได้แค่ไหน?

> AI ถูกใช้เป็นผู้ช่วย ไม่ใช่ตัวตัดสินใจสุดท้าย ระบบให้ผู้ใช้ตรวจสอบก่อนบันทึกอาหาร มี scope guard จำกัดคำถาม มี timeout/rate limit และไม่ควรตอบเชิงวินิจฉัยโรคหรือรักษาโรค

### Q6: ข้อมูลอาหารเปลี่ยนแล้วประวัติผู้ใช้จะเพี้ยนไหม?

> ตอนบันทึกอาหาร ระบบเก็บ nutrition snapshot ของรายการนั้นไว้ ทำให้ประวัติผู้ใช้ยังสะท้อนค่าที่บันทึก ณ เวลานั้น ไม่ถูกเปลี่ยนย้อนหลังแบบไม่ตั้งใจ

### Q7: ทำไมต้องมี gamification?

> การติดตามสุขภาพต้องทำซ้ำทุกวัน gamification ช่วยเพิ่มแรงจูงใจและความต่อเนื่อง เช่น ภารกิจรายวัน reward และตัวละคร แต่ยังยึดข้อมูลสุขภาพเป็นแกนหลัก

### Q8: ระบบรองรับคนไทยอย่างไร?

> มีภาษาไทยเป็นหลัก รองรับอาหารไทย ชื่ออาหารตามภูมิภาค การค้นหาเมนูไทย และใช้เกณฑ์ BMI สำหรับชาวเอเชีย รวมถึงออกแบบ flow ให้ผู้ใช้เข้าใจง่าย

## 27. Closing Script

> ผู้ใช้ไม่ได้เห็นแค่ตัวเลขแคลอรี่ แต่เห็นภาพรวมว่าเป้าหมายคืออะไร วันนี้ทำไปถึงไหน ควรกินอะไรต่อ มีความเสี่ยงอะไรที่ต้องระวัง และความคืบหน้าในระยะยาวเป็นอย่างไร

## 29. Fallback Script เมื่อเดโมบางส่วนไม่ขึ้น

### ถ้า AI ไม่ตอบ

> ตอนนี้ AI service อาจยังไม่พร้อมใน environment เดโม แต่ระบบมี health check และ kill switch ถ้า AI ใช้งานไม่ได้ ฟีเจอร์หลักอย่างบันทึกอาหาร dashboard recommendation และ progress ยังใช้งานได้ตามปกติ

### ถ้า Health Connect ไม่มีข้อมูล

> ข้อมูลจาก wearable ขึ้นกับ permission และการ sync ของ Health Connect/Samsung Health ถ้าไม่มีข้อมูล ระบบจะยังบันทึกอาหาร น้ำ น้ำหนัก และคำนวณเป้าหมายได้ตามปกติ โดยไม่พึ่ง wearable เป็นแกนหลัก

### ถ้า notification ไม่เด้ง

> Notification บนมือถือขึ้นกับ permission ของ OS แต่ backend ยังบันทึก notification ไว้ในระบบ และ Flutter สามารถดึง unread count หรือรายการแจ้งเตือนมาแสดงได้

### ถ้าอาหารค้นไม่เจอ

> ถ้าอาหารยังไม่มีในฐานข้อมูล ผู้ใช้สามารถใช้ quick add หรือ AI estimate ได้ และข้อมูลอาหารใหม่สามารถเข้าสู่ flow moderation/admin review เพื่อเพิ่มเข้าฐานข้อมูลกลางในภายหลัง
