Admin ทำอะไรได้: สร้าง/แก้ไข/ลบ (soft) อาหารใน foods พร้อม version history → จัดการ dish_categories, dishes, units, ingredients → กำหนด allergy flag ให้อาหาร → จัดการ recipe และขั้นตอนการทำ → อนุมัติชื่ออาหารตามภูมิภาค (food_regional_names) → จัดการ health_contents → ดูและแก้ไขข้อมูล users ทุกคน → ลบ user แบบ hard-delete • Admin มองเห็นข้อมูลทุก user — ไม่ถูก ownership check จำกัด

🔗 ความสัมพันธ์ข้ามฝั่ง (Cross-Domain FK)

  • detail_items.food_id → foods.food_id — User log เชื่อมกับ Admin-managed catalog
  • detail_items.food_version_id → food_versions.food_version_id — snapshot ณ เวลาบันทึก
  • user_allergy_preferences.flag_id → allergy_flags.flag_id — User เลือก flag ที่ Admin ดูแล
  • user_favorites.food_id → foods.food_id — User mark favorite บนอาหารที่ Admin สร้าง
  • recipe_reviews / recipe_favorites → recipes — User interact กับ recipe ที่ Admin จัดการ
  • food_versions.created_by → users.user_id (role=admin) — ติดตามว่า Admin คนไหนแก้ไข

🔄 Moderation Workflow — Admin อนุมัติข้อมูลจาก User

User ส่งข้อมูลเข้า temp tables → Admin ตรวจสอบ → Approve เข้า production tables

Workflow: (1) User พบอาหารที่ไม่มีในระบบ → ส่งผ่าน POST /foods/auto-add → เข้า temp_food สถานะ pending → (2) Admin เห็นที่ GET /admin/temp-foods → อนุมัติ (POST /admin/temp-foods/{id}/approve) → ระบบ insert เข้า foods และสร้าง verified_food record → backfill detail_items ของ User ที่รอ → (3) ถ้า Admin ปฏิเสธ → DELETE /admin/temp-foods/{id} → สถานะ rejected • กระบวนการเดียวกันใช้สำหรับ food_regional_name_submissions

📋 Role Access Matrix — สิทธิ์การเข้าถึงแต่ละตาราง

สรุปสิทธิ์ CRUD ของแต่ละ Role ตามที่ enforce จริงใน backend

🟢 CRUD เต็ม 🟡 เฉพาะของตัวเอง 🔵 อ่านได้ (Public) 🟣 CREATE only 🔴 Admin เท่านั้น ⚪ ไม่มีสิทธิ์โดยตรง
กลุ่ม ตาราง (Table) 👤 User (role_id=2) 🛡️ Admin (role_id=1) หมายเหตุ
Identity users READ own UPDATE own soft DELETE READ all UPDATE any hard DELETE User ลบบัญชีตัวเองได้ (soft, 30วัน), Admin ลบจริง (cascade)
Identity roles READ (implicit) READ / UPDATE user's role_id Admin เปลี่ยน role_id ของ user ได้ผ่าน PATCH /admin/users/{id}
Auth email_verification_codes CREATE (request) READ own — ส่ง OTP ผ่าน POST /verify-email
Auth password_reset_codes CREATE (request) READ own — Flow: request → verify (birth_date) → confirm new password
Food Catalog foods READ (public) CREATE / UPDATE / soft DELETE GET /foods เป็น public; POST /foods admin-only
Food Catalog food_versions READ (via food) CREATE (on food edit) เก็บประวัติการแก้ไขอาหาร, backfill detail_items ที่เชื่อม food นั้น
Food Catalog dish_categories, dishes READ (public) CRUD ใช้จัด category ของอาหาร
Food Catalog units READ (public) CRUD หน่วยวัด เช่น กรัม, ช้อนโต๊ะ, ถ้วย
Food Catalog allergy_flags READ (select prefs) CRUD Master list ของ allergy เช่น gluten, dairy, nuts
Food Catalog food_allergy_flags READ (implicit) CREATE / DELETE กำหนดว่าอาหารนั้นมี allergy ใดบ้าง
Food Catalog ingredients, food_ingredients READ (via recipe) CRUD ส่วนผสมของอาหาร ใช้คำนวณโภชนาการ
Food Catalog food_regional_names READ (search) CREATE (on approve) / DELETE ชื่ออาหารตามภูมิภาคไทย เช่น "ข้าวมันไก่" ต่างจังหวัด
Food Catalog food_regional_popularity READ (search weight) UPDATE ความนิยมของชื่ออาหารในแต่ละภูมิภาค
Recipes recipes READ CREATE / UPDATE สูตรอาหาร ผูกกับ foods
Recipes recipe_steps, recipe_tips, recipe_tools READ CRUD รายละเอียดวิธีทำและอุปกรณ์
Recipes recipe_ingredients READ CRUD ส่วนผสมของสูตรอาหาร
Recipes recipe_reviews CREATE / READ / UPDATE (own) READ all / DELETE (moderate) User ให้คะแนนและ comment recipe
Recipes recipe_favorites CREATE / DELETE (own) — User bookmark recipe ที่ชอบ
Logging meals CREATE / READ / UPDATE / DELETE (own) — POST /meals/{user_id}, PUT /meals/{user_id}/{meal_id}
Logging detail_items CREATE (via meal) / READ (own) — เก็บ food_snapshot ป้องกัน data drift เมื่ออาหารถูกแก้ไข
Logging daily_summaries READ (own, auto-gen) READ all ระบบ generate ให้อัตโนมัติ User ไม่ต้องสร้างเอง
Logging water_logs CREATE / READ / UPDATE (own) — unique(user_id, date_record) — 1 record ต่อวัน
Logging weight_logs CREATE / READ (own) — ใช้คำนวณ BMI trend และ goal progress
Logging exercise_logs CREATE / READ (own) — ใช้หักแคลอรี่ที่เผาผลาญออกจาก net intake
Preferences user_allergy_preferences CREATE / READ / DELETE (own) — ใช้กรองอาหารที่เสี่ยงต่อ allergy ใน recommended foods
Preferences user_favorites CREATE / READ / DELETE (own) — bookmark อาหารที่ชอบ
Gamification user_gamification READ own UPDATE (sync tama points) READ all / UPDATE any (points, tier, badges) PATCH /admin/users/{id}/tama — Admin ปรับแต้มได้โดยตรง
Notifications notifications READ own / UPDATE (mark read) CREATE (system push) / READ all ใช้ FCM token สำหรับ push notification
Content health_contents READ (published only) CRUD / PUBLISH บทความสุขภาพ ระบบกรองเฉพาะที่ is_published=true ให้ User
Moderation temp_food CREATE (submit) READ all / DELETE (reject) POST /foods/auto-add → pending → Admin review
Moderation verified_food — CREATE (on approve) สร้างอัตโนมัติเมื่อ Admin approve temp_food
Moderation food_regional_name_submissions CREATE (submit) READ all / APPROVE / REJECT User submit ชื่ออาหารภาษาท้องถิ่น → Admin ตรวจสอบ
